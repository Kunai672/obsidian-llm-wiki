## Decisions

1. **Path resolution at call time**: `_wiki_root()` and `_raw_root()` are functions, not module-level constants, so they resolve relative to current working directory. This allows tests to run in temp directories.

2. **Code-owned files**: `index.md`, `log.md`, `overview.md`, `lint-report.md` are never edited by LLM. They are regenerated by code only. This prevents LLM from corrupting the catalog or log.

3. **Wikilink stems**: Unique filename stem (without `.md`) used as wikilink target. Case-insensitive resolution, stored lowercase.

4. **Frontmatter required fields**: `title`, `type`, `summary`, `sources`, `tags`, `updated` - all mandatory. Enforced on write and lint.

5. **Atomic writes**: All file writes use temp file + rename for crash safety.

6. **Fake LLM backend**: Selected by `LLMWIKI_BACKEND=fake`. Uses `FakeLLMClient` with canned responses keyed by prompt substring. No network in tests.

7. **Orphan detection**: Excludes inbound links from code-owned pages (index, log, overview, lint-report) since they link to everything.

8. **BM25 search**: Pure Python implementation, no external dependencies. Searches title, summary, tags, and body.

9. **Two-step query**: Separates page selection from answer generation for better accuracy and token efficiency.

10. **Append-only log**: Exact prefix format `## [YYYY-MM-DD] <op> | <title>` for grep compatibility.

## Known Issues

1. **Chunking not fully implemented**: Ingest truncates at 12000 chars instead of chunking and merging multiple LLM calls. For long sources, content is lost.

2. **Search pre-filter not integrated**: Query step 1 should use search when >200 pages, but currently always uses full index.

3. **Deep lint LLM errors silent**: Deep lint catches all exceptions silently; failures are not reported.

4. **No watcher for raw/**: No automatic ingestion when files are dropped in `raw/`.

5. **No embedding search**: BM25 is keyword-only; semantic search would require embeddings.

6. **Image/attachment handling**: Raw assets folder exists but no code references or processes attachments.

7. **Batch ingest**: No command to ingest multiple files at once.

8. **Conflict resolution on re-ingest**: Append action merges sources/tags but replaces title/type/summary/updated from new content. May not be ideal for all cases.

## Follow-ups

1. **Embeddings search**: Add optional sentence-transformers or local embedding model for semantic search. Could use `chromadb` or pure Python with numpy.

2. **Image handling**: Extract images from raw sources, save to `raw/assets/`, reference in wiki pages.

3. **Batch ingest**: `python -m llmwiki ingest raw/*.md` or `ingest --dir raw/`.

4. **Watcher**: File system watcher (watchdog) to auto-ingest new raw files.

5. **Proper chunking**: Split long sources at ~12000 chars, make multiple LLM calls, merge edits.

6. **Search integration in query**: When >200 pages, use search to pre-filter before step 1.

7. **Better deep lint error reporting**: Log LLM failures instead of silently ignoring.

8. **Export commands**: Export wiki to single markdown, HTML, or PDF.

9. **Graph visualization**: Generate graph of entity/concept relationships.

10. **Configuration file**: `llmwiki.yaml` for default paths, chunk size, search params, etc.

11. **Git integration**: Auto-commit wiki changes with meaningful messages.

12. **Multi-user/locking**: File locking for concurrent access.
